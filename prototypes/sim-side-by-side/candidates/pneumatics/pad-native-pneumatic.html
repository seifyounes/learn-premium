    For the Owner

    • Real: the engine (pad-native-pneumatic.engine.mjs, no DOM) decides every frame: valve states → which lines hold air (union-find through the open valve paths) → pilots shift spools after 40 ms → pistons travel → rollers make/break → next event. The view only draws its state. check-pad-native-pneumatic.mjs runs it in Node: sequence A+ B+ B− A−, no pilot conflict, the step table in circuit.md, return to rest, hold-to-repeat, and it proves the conflict check bites on the naive wiring (24/24 PASS).
    • Simplified: kinematic, not physical. Pistons move at constant speed (A 1.0 s out / 0.8 s back, B 0.9 / 0.7 s), lines fill instantly, no loads, forces or flow restrictors. Enough for sequence teaching; not for timing or force questions.
    • Hand-drawn: the circuit layout is hand-placed coordinates for this one circuit. Shipping needs an auto-layout (or an agent-authored layout block) from the circuit JSON, a symbol set for 5/3, 3/2 pilot, timers, AND/OR, flow control, and the electro-pneumatic (solenoid + relay) half.
    • Weight: first load 58 KB of our own files (HTML 5 KB, CSS 9 KB, view 23 KB, engine 12 KB, shared pad.css 8 KB; uncompressed from the static server) plus the shared pad web fonts. No libraries: one HTML, one CSS, one engine module; fonts come from the shared pad.
    • Touch: works. START is a 64 px printed key and the START symbol in the circuit is tappable too; holding either repeats the cycle. The circuit scales to the phone width, labels grow to stay ≥ 12 px.
