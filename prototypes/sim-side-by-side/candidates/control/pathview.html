For the Owner

Real: the hosted PathView at view.pathsim.org (GitHub Pages; no X-Frame-Options or CSP, so it iframes), running PathSim in Pyodide in a Web Worker. The model is our own feedback-k.pvm (Step → Adder "+−" → Amplifier K → TransferFunctionNumDen [1]/[1, 2, 0] → Scope, feedback from y), written to the documented .pvm spec and passed as ?model=. Our local server sends no CORS header, so this page fetches the .pvm and hands it over as a data: URL, which also works on a phone.

Accuracy: run in this embed, the scope's y(t) peaks at 1.1630331 at t = 1.815 s (overshoot 16.303 %, python-control: 16.303 %). The same .pvm through PathView's own pvm2py in CPython PathSim 0.25.1 gives the identical trace and 2 % settling at 4.04 s. The tool shows the curve, not those numbers: the student reads them off the scope.

First load: about 34 MB transferred: the editor app 0.85 MB, Pyodide core 5.1 MB, NumPy + SciPy 18.3 MB, matplotlib and friends (PathSim pulls them in) 9.7 MB, PathSim 0.2 MB. The worker's requests do not show in the page's network log, so the sizes are the compressed sizes of exactly those files. The diagram appears in about 5 s; Run is ready after about 21 s even with a warm cache on this laptop. Touch: partial. It pans and zooms, but it is an editor: panels crowd a 390 px screen and there is no viewer-only mode. Light theme forced with ?theme=light; its look is PathView's own, not the pad.

To ship: self-host a pinned build (we depend on a third-party site and its CDN Pyodide), a viewer mode, and a parameter allow-list, because every .pvm param is a Python expression.
